# Pixel Shading Studio — Technical Architecture

## Adaptive workspace (2026-10-24)

`useWorkspaceLayout` classifies available CSS space: phone below 600px, a side dock for tablet widths below 1200px, and a side dock for short (below 600px) wide viewports. Full desktop keeps simultaneous inspectors. The phone bottom dock has ordinary and expanded editing states, with a constrained-height editing arrangement. `useVisualViewport` bounds workspace height to the visible viewport, sets constrained editing from its actual height (including iOS keyboard behavior), tracks its top offset for dialog placement and reveals focused inputs; safe-area insets are CSS presentation only.

Inspectors remain nonmodal complementary regions so the live artwork stays interactive. Secondary tasks use the native top-layer `WorkspaceDialog`, with a persistent heading, scrollable content, focus return and Tab endpoints. Neither dock state nor modal state belongs to scene settings. ReferenceViewport and its keyed ReferenceSession stay in the same React tree across layouts; only renderer retry changes that key. Comparison direction changes through a preview-height container query. PreviewPresentation's authoritative native canvases, store, scheduler, camera/light owners, native pipeline and PNG export are reused unchanged. The only gesture ownership change is a 48px touch acquisition area for the light handle (mouse remains 36px).

`LocalPersistence.currentError` is transient status metadata for compact, actionable failure reporting; serialized settings and preset schemas remain version 1. The existing tuned boundaries `[0.22, 0.5, 0.75]`, palette bytes and binary transparency are preserved. See [adaptive QA](evidence/ADAPTIVE.md) for exact observed checks and unrun items.

Imported static models pass bounded local preflight and ref-counted ownership; only filename/format/bundle SHA-256 enters JSON, and reload requests matching files. Limits, inactive-mode unions, artist-order palette rules and reset boundaries below remain the actual contracts. No cloud service, runtime remote asset, animation/material authoring or additional image format is present.

PSS-20 production/control checks and independent downloaded-pixel comparisons preserve these owners. UI dispatches validated settings actions; it does not directly mutate meshes or frame buffers. Never show an enabled control for a capability absent from the current increment.

The store owns serializable scene settings: subject descriptor/transforms, camera pose/target/roll/projection, lights, canvas/framing, shading/ramp/palette, dithering, outline, background, ground/shadow options. Keep schema version separate from transient revision counters. A bounded action increments relevant dirty revisions. ### Implemented settings contract (PSS-02)

The implementation is `src/domain/settings.ts`, `defaults.ts`, `constraints.ts`, `validation.ts` and `src/app/studioStore.ts`. The factory and shared vanilla Zustand store expose `getState`, `getInitialState` and `subscribe`; React can subscribe with Zustand's `useStore(studioStore, selector)`. Direct `setState` is omitted from the public API. Types are readonly; validators construct detached plain objects/arrays, and commits preserve references for unchanged sections so selectors can stay small.

`SceneSettings.schemaVersion` is **1**. All defined fields are required, each union accepts only its own fields, and unknown fields/versions fail validation. There are no historical migrations or storage writes. `validateSceneSettings(unknown)` returns `{ok:true,value,notices}` or `{ok:false,issues}` with the first deterministic error's field path. It normalizes hex/hash casing and negative zero; it does not sort colors, remove duplicates, coerce strings, or clamp numeric values. Persist **only** `store.getState().settings`; actions, preview, status, revisions and resources are outside that object. Export uses `settings.canvas` dimensions exclusively.

The persisted sections are `subject`, `camera`, `lighting`, `canvas`, `framing`, `shading`, `palette`, `dither`, `outline`, `ground`, `shadows`, and `background`. Seven primitive variants have only relevant parameters. The square pyramid has a single `baseSize`; torus `radius` is the major radius and `tubeRadius` must be smaller. An imported descriptor contains only `fileName`, `format` (`glb`/`gltf`) and a lowercase SHA-256 hex digest; bytes, resource handles and missing-asset status belong to PSS-16 runtime import ownership outside settings. The receiver is an independent XZ plane at its configured position.

Object position, camera/light position and target, and ground dimensions use world units. Object Euler rotations and camera roll/FOV use **degrees**; controllers convert to radians. The normalized surface-to-light vector is `(directional.position - directional.target) / length`, derived rather than stored. Both light and camera endpoints must be at least `0.000001` world units apart. Camera pose and projection live independently of object transforms. Orthographic projection stores vertical world span and zoom; perspective stores FOV and zoom. PSS-05 implements projection conversion/presets and explicit reference reframing; PSS-08 derives measured native fitting without writing that camera state.

Declared limits in `LIMITS` are inclusive unless a relationship below says otherwise:

| Fields | Constraints |
| --- | --- |
| Canvas and requested fit-box axes | Integer 1–1024; canvas at most 1,048,576 pixels. GPU/allocation capability adds runtime constraints later |
| World geometry dimensions | 0.001–1000 |
| Camera position/target axes / orthographic vertical span | −100,000,000–100,000,000 / 0.00000001–100,000,000 (PSS-05 camera-only bounds) |
| Object/light/ground positions and light targets | −10,000–10,000 per axis |
| Rotation / roll | −360–360 degrees |
| Scale | −1000–1000 with magnitude at least 0.001; signed/nonuniform scale is supported |
| Segments | Integer 1–128; circular segments at least 3; sphere height segments at least 2 |
| Camera zoom / perspective FOV | 0.01–100 / 1–179 degrees |
| Light intensity | 0–10 for directional and ambient |
| Brightness / contrast / distribution exponent | −1–1 / 0–4 / 0.1–4 |
| Palette | 1–32 opaque `#RRGGBB` colors, preserving artist order and duplicates |
| Fit offsets / per-edge padding | Integer −1024–1024 / 0–1023; padding must leave a drawable pixel on both axes, including in manual mode |
| Dither strength / transition width | 0–1; transition width is in shade intervals, absent for diffusion |
| Pattern scale / outline thickness | Integer 1–8; scale exists only for Bayer/blue noise |
| Pixel-soft shadow radius / shadow strength | Integer 0–4 / 0–1; hard treatment has no radius |
| Preview zoom / pan | 0.125–64 / −1,000,000–1,000,000 CSS pixels, view-only |

Every numeric field must be finite. `validateNumber(value, declaredBounds)` is also available for controls; custom bounds are checked and enforced, never used as silent truncation. `validateColor` and `deriveLightDirection` are pure reusable helpers. `resolveFitBox` takes validated settings and reports the effective box constrained to the padded canvas. Validation retains the requested box and returns a `fit-box-clamped` notice in pixel-fit mode. PSS-08 consumes this effective maximum, applies integer placement and publishes actual category-mask bounds as described below. Manual mode retains valid fit settings for reuse.

`shading.normals` is independent of `shading.tone`: continuous tone plus smooth/flat normals supplies smooth/flat reference modes, and the other tone variants are cel, bands and palette. The canonical default uses **smooth normals and four discrete bands** so the specified four blue colors are ready for the later exact-color renderer. `palette.colors` is the single ordered ramp/nearest-color list. Shadow/base/highlight colors are explicit ramp-generation inputs; PSS-10 supplies explicit linear-RGB generation and non-resampling level changes. PSS-11 implements custom editing, resampling, presets and nearest-color mapping, detailed below. Cel/band thresholds number `colors.length - 1` and increase strictly inside `(0,1)`; a one-color palette has no thresholds. Intensities may exceed one; the processor will saturate its normalized illumination signal as specified. Dither, outline, background, receiver appearance and shadow treatment are discriminated unions, so disabled/irrelevant fields cannot leak into persisted data. `palette.effectPolicy` chooses explicit effect colors or strict palette mapping.

`actions.setSection(section, completeSection)` validates the resulting full scene. Numeric edits outside these bounds return an error and preserve the entire state. Geometry selection replaces only the geometry descriptor with that primitive's defaults; it preserves transforms, camera, light, framing and styling. It does not implement a camera reframe. `restoreSettings(unknown)` validates the entire snapshot before publishing settings and revisions together in **one** store update. Failed and normalized-equivalent edits publish nothing. Notices are returned to the caller for future UI display.

Reset boundaries:

- `resetTransforms()` resets only the subject transform; `resetSection('subject')` resets descriptor and transform.
- `resetSection(section)` restores only that section. Camera never resets object transforms; lighting never resets palette or shadows; shadows never resets the receiver.
- `setPaletteColors(colors)` preserves custom thresholds for the same color count. An explicitly changed count redistributes thresholds uniformly in the active cel/band mode in the same transaction, without generating/resampling any colors. `resetSection('palette')` restores the cool-blue colors/effect policy and evenly spaced thresholds for the current cel/band mode; it preserves lighting, normal treatment, tone mode and signal controls.
- `setShadingLevels(count)` (PSS-10) retains the first `count` colors and existing boundaries. Growth appends the current highlight bytes and evenly splits only the remaining interval after the last boundary; shrink removes trailing entries/boundaries. The inspector stages the count, discloses removals and requires **Apply levels**. No existing entry is interpolated automatically. `generateShadingRamp()` explicitly replaces colors from shadow/base/highlight while preserving boundaries.
- `resetSection('shading')` restores default shading while deriving threshold count from the retained palette. Cross-section violations otherwise reject the reset. For example, resetting canvas to 64×64 fails if retained padding consumes that canvas; reset framing or change padding explicitly before retrying.
- `resetScene()` resets all persisted sections in one commit and preserves preview/tool/status state. `resetPreview()` restores only presentation/tool defaults (8× zoom, centered pan, final mode, checkerboard on, grid off, camera tool).

Dirty revision counters start at zero; runtime mounting must request its initial capture. Each successful changed settings commit increments `settings` and `style` once. `capture` increments for subject, camera, canvas, framing, normal-treatment, or receiver-geometry changes. `shadow` increments for those capture dependencies, directional source/target changes, or any shadow-settings change. Color/intensity/ambient, palettes, tone/signal, dither, outline and background reuse capture. The conservative style revision remains unchanged; PSS-14 separates runtime outline compositing from cached lighting/quantization within that scheduled work. Receiver appearance/color also reuse capture and shadow visibility. Shadow invalidation is conservative even while shadows are disabled, allowing later enabling to use the latest state. Preview/tool changes increment only `view`; busy/error status increments no pixel revision. No counters are persisted. This gives later scheduling tasks one invalidation contract without allocating runtime resources now.

## Scene and controllers

### Implemented reference runtime (PSS-04)

`components/ReferenceViewport.tsx` owns one `ReferenceSession` effect inside the existing StrictMode workspace. Its `scene/referenceRuntime.ts` owns one canvas, directly constructed WebGL2 `WebGLRenderer`, scene, cameras, lights, subject, resize observer, store subscription, context listeners and `scene/invalidation.ts` scheduler. No renderer or pixels enter React state or settings JSON. `referenceStatus` is transient store metadata, distinct from general operation status and dirty revisions. Changes coalesce into one requested frame; drawing does not request another frame. Preview/tool changes do not render except `preview.referenceWireframe`, a view-only setting reset by Reset view. PSS-07 extends this same scheduler with capture/style/presentation work and generation ownership, as described below.

`scene/primitives.ts` dispatches validated descriptors to standard Three geometries. The pyramid uses a closed four-sided cone of radius `baseSize / sqrt(2)`, rotated Y by 45 degrees: its square base has axis-aligned XZ sides, its apex points +Y, and its material uses flat faces. Plane geometry lies in XY and renders on both sides. Other reference materials use smooth Lambert lighting and the current base color, directional light and ambient defaults. Exact palette/band processing is not claimed. The mesh-edges view uses the same geometry/material with emissive edges so planar segment changes can be inspected.

`scene/subject.ts` separates the user transform parent from a normalization group and owned `SubjectContent` (`Object3D` plus disposer). The latter accepts a static group later without introducing import machinery. XYZ Euler degrees become radians at the boundary; signed nonuniform scales use Three's inverse-transpose normal matrix. Geometry/material replacement occurs only when descriptor values change; transform/light/camera edits reuse geometry. Replacement and final disposal release resources at their owner. Helper and future ground roots use separate layers (subject 0, helper 1, ground 2); no ground or shadows are rendered yet.

PSS-05 replaces the temporary PSS-04 runtime-only reference fit with a manual world-space camera. Shape/parameter/transform edits preserve the saved camera. **Reframe reference** explicitly measures transformed subject bounds and commits a centered camera pose/span through the validated camera action. Reset geometry/transforms does not reframe; Reset scene restores the canonical camera exactly. This removes a hidden target/scale that would otherwise cancel camera pan/zoom. Reframe is a user action, not a fitting loop or native pixel-fit implementation. Expanded camera-only position/span limits accommodate PSS-04's supported tiny/large shapes without expanding geometry, light or object bounds. Impossible reframes/conversions reject atomically with visible guidance; manual near-plane clipping remains possible by design.

The display reference can use MSAA and capped DPR (at most 2 and 4,194,304 display pixels, also bounded by GPU axis limits). This cap applies only to reference presentation, never to a native output size. PSS-07 must allocate its own exact-size non-MSAA target using this same renderer. There is no output frame, capture target or export action in PSS-04.

Unavailable WebGL2, allocation/driver/shader failures and actual context loss produce visible status and disable reference-dependent actions. Loss cancels pending work, disposes the old scene/renderer and removes its canvas. **Retry renderer** mounts a fresh StrictMode session and reconstructs from current validated settings; there is deliberately no automatic restoration of a discarded context. Final unmount also cancels RAF, removes subscriptions/listeners/observers, disposes resources, and releases the context when supported. Later capture/export work must extend this single recovery owner and invalidate its own output on failure.

Development-only `?scene-checks` reveals explicit diagnostics and simulations for context loss, unavailable context, allocation failure and a full keyed remount. Diagnostics refresh on request rather than polling, expose real renderer counters and are omitted from the production UI. Browser evidence, including resource plateaus and actual retry checks, belongs in PROGRESS.md; unit tests do not stand in for GPU rendering.

### Implemented camera controller (PSS-05)

`scene/cameraController.ts` owns one installed `three/addons/controls/OrbitControls.js` instance, its unrolled orthographic/perspective source cameras and separate derived render cameras. The existing runtime owns this controller and disposes it before the renderer. `settings.camera` is the only authoritative pose/target/roll/projection state. Inactive cameras and controls are runtime caches, never serialized. Numeric edits, presets, restore and reset apply synchronously with `change` publication suppressed. Gestures publish through `setSection('camera', ...)` once per controls change; invalid movement rolls back to the last validated pose. Rendering and resize derivation publish no settings. Damping and autorotation are disabled; no controls update loop runs while idle.

`scene/referenceCamera.ts` also derives ground-aware orbit limits. An active visible or shadow-only receiver caps polar angle at the horizon and keeps the camera above its world Y position with minimal clearance. The horizon cap prevents parallel orthographic rays from revealing the receiver underside. `CameraController` recomputes limits on camera/ground changes, corrects below-limit saved/numeric/preset poses through the validated camera action, and constrains post-pan/dolly positions before publication. Ground off restores full polar orbit. Corrections retain the target, roll and projection; an otherwise coincident camera is moved along Z within camera bounds. Subject/ground transforms and the settings schema stay independent.

`scene/referenceCamera.ts` provides pure view/distance/projection/reframe helpers, unrolled pose configuration and rolled render derivation. Exact top/bottom use a deterministic right axis (+X), with −Z/+Z up respectively. Applying numeric/preset pole poses restores exact position after OrbitControls' internal epsilon nudge. Subsequent gestures use its safe polar clamp. The render camera copies source pose/projection, then rotates local Z by stored roll. Pan displacement is rotated into the displayed rolled axes; roll never changes the orbit up vector. Derived near/far planes include transformed subject depth when possible and remain finite/ordered for tiny/large bounds. Future pixel fitting must alter only a derived render camera, never this source.

Projection switching preserves target, view direction and roll and matches vertical scale at the target plane. Orthographic→perspective selects 50° FOV/zoom 1 and derives distance; perspective→orthographic derives span at the target plane and represents it with bounded span/zoom. Depth foreshortening is expected and explained. Inputs retain finite validation: FOV 1–179°, zoom 0.01–100, endpoint separation at least 0.000001 world units, camera axes ±100 million and span 1e−8–100 million. Camera bounds were widened only to preserve existing extreme reference reframing after removing runtime scaling; the version-1 JSON shape is unchanged.

`components/CameraInspector.tsx` exposes projection/FOV/span/zoom, distance, XYZ position/target, roll, seven views and camera-only reset using the existing numeric controls. Reset camera intentionally restores zero roll and orthographic defaults; Reset view and object resets preserve camera settings. The focused reference supports arrows to pan and Shift+arrows to orbit. Default pointer/touch gestures follow [OrbitControls](https://threejs.org/docs/pages/OrbitControls.html). Camera and idle Move light tools enable camera gestures. A handle-owned pointer temporarily disables them through `setLightGestureOwned`; Pan preview remains unavailable and paused. Numeric camera edits remain available regardless of tool.

One renderer/context and one scene continue to own all drawing. PSS-06 adds light dragging and PSS-07 adds native frames below. PSS-08 locks OrbitControls pan/zoom and numeric camera pose/scale in pixel-fit mode, while orbit/roll/projection remain available. An explicit manual switch preserves pose, transforms and requested fit values. The larger reference retains the saved projection; only native output is fitted. Preview navigation, export and persistence remain later work. PSS-06/09 must preserve gesture ownership and use the correct displayed rectangle/rolled render camera for their input mapping. Diagnostics now include camera quaternions, source pose, projection/near/far, control-change counts and dirty revisions for real-browser verification.

### Implemented lighting and handle (PSS-06)

`domain/lighting.ts` derives one normalized surface-to-source `L = normalize(position − target)` and decoded linear-sRGB directional/ambient energies from validated settings. Position/target are the only saved direction source. `deriveLighting` rejects nonfinite/out-of-range inputs and endpoint separation below 1e−6. `lambertIllumination` accepts unit N and L in the same space and returns unclamped linear RGB `A + D * max(dot(N,L),0)`. Multiply by decoded base reflectance, then saturate only for display conversion or the later normalized tone signal. Direction/ambient intensities are 0–10; existing brightness bounds remain −1–1 for later tone processing. Zero directional intensity leaves ambient intact. Presets use canonical world axes/target and white light: upper-right (+3,+4,+5), upper-left (−3,+4,+5), overhead (0,+5,0), side (+5,0,0), and flat ambient (directional 0, ambient 1). Other presets use directional 1/ambient 0.2. Presets/reset change lighting alone.

`scene/referenceLighting.ts` adapts the shared energies to the existing MeshLambertMaterial. The installed Three r186 `lights_lambert_pars_fragment` multiplies both directional and ambient irradiance by `BRDF_Lambert = reflectance / PI`; the adapter scales both runtime light intensities by PI to cancel that factor. It positions the runtime directional cache at unit L with target zero. These are derived caches, never a second editable pose. The runtime explicitly uses NoToneMapping and sRGB output, with no environment map. This adjustment gives the later CPU lighting the same unit-intensity meaning; do not copy the adapter's PI into CPU math. Reference wireframe remains a presentation-only emissive topology aid.

`scene/lightHandle.ts` owns a reference-only sphere marker, ring and arm, including their geometries/materials. Every descendant uses helper layer 1, has depth testing/writing off and never enters `SceneSubject`. The historical beauty camera enabled helper layer 1; PSS-09 draws its screen proxy separately as an SVG overlay; fitting cameras use subject layer 0 only; PSS-15 enables ground layer 2 temporarily in aligned effect passes. Handle updates and light edits do not replace subject geometry or affect subject bounds. Disposal is idempotent.

The marker is a direction proxy, since actual light positions are frequently outside a useful reference view. Its sphere radius is 32% of the displayed image rectangle's shorter CSS axis converted to world units at the light target. Perspective caps world radius at 45% of target depth. The screen-facing ring and fixed-size marker do not imply distance/attenuation. A target behind/outside depth clipping hides the helper; offscreen positions remain editable numerically. Hit testing uses the retained fitted native camera and the actual panel image rectangle after zoom, pan and letterboxing, including comparison borders and workspace offsets. There is no DPR multiplication in CSS-coordinate input. Pointer points map to a target-centered virtual sphere's front hemisphere, with outside points normalized onto its equator. ## Native rendering and processing

The central design choice is GPU rasterization plus a CPU pixel pipeline at native resolution. This keeps ordered and sequential dithering together and makes exported bytes authoritative. It costs small readbacks, so cache geometry data and profile before optimizing. Do not create separate GPU approximations for preview and CPU algorithms for export.

| Stage | Owner | Tradeoff |
| --- | --- | --- |
| Geometry/depth/normal/category and shadow visibility | GPU / Three | Reliable triangle visibility at native W×H; avoid CPU rasterizer and float readback requirements |
| Lambert light, tone controls, palette/ramp selection | CPU pure functions | Geometry-aware shading with exact byte-controlled output, cached normals and easily verified color math |
| Bayer and blue noise | CPU threshold mapper | GPU implementations would be fast, but add a second algorithm path/readback without benefit at small images |
| Floyd–Steinberg | CPU sequential scan | True neighbor-error dependency; a normal fragment shader cannot substitute a parallel noise overlay |
| Outlines and final compositing | CPU binary masks/bytes | Exact integer neighborhoods, effect color policy and alpha; reuse buffers |
| Presentation and PNG | Canvas/browser APIs | A single finished byte image, view-only nearest scaling, no GPU re-upload for export |

Palette matching is O(W×H×paletteSize), with paletteSize at most 32. Diffusion is O(W×H) plus matching and two bounded error rows; mask dilation can use separable/max-window passes if profiling warrants it. At 256×256, one four-channel byte buffer is 256 KiB; a handful of such buffers and float working arrays fit comfortably in a normal desktop budget. The 1024-axis custom limit is a guardrail rather than a responsiveness promise; failures are reported before/at allocation. Profile actual synchronization costs, which can dominate arithmetic, before adding workers or GPU passes.

### Capture format and lighting

At PSS-07, rasterize view-space normals with alpha as a coverage/category code into an unsigned-byte RGBA native target. RGB encodes normal components from [-1,1] into [0,255]; alpha 255 identifies subject, 128 identifies the independent receiver, and 0 is background. Do not treat this category alpha as color transparency. Reconstruct/normalize normals after readback. Use a NoColorSpace data target, no blending, no output/tone mapping, depth testing on, no MSAA or mipmaps, nearest filters. Normal byte precision is sufficient for controllable bands; test threshold stability and document it. Do not require float targets/extensions or readbacks.

Three provides explicitly sized render targets and byte readback; its renderer also supports asynchronous readback in compatible versions. Verify selected APIs rather than assuming signatures. [WebGLRenderTarget](https://threejs.org/docs/pages/WebGLRenderTarget.html), [RenderTarget sampling](https://threejs.org/docs/pages/RenderTarget.html), and [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html).

CPU Lambert lighting is geometry-aware: transform the surface-to-light direction into the render camera's normal space, compute `max(dot(normal, lightDirection), 0)`, multiply directional color/intensity and visibility, and add ambient. Light RGB and base colors are decoded to linear-sRGB. Compute normalized illumination for scalar ramps using linear luminance and documented clamping; derive continuous linear RGB for smooth/palette mode from base reflectance times illumination. Keep brightness/contrast/distribution functions pure. Camera changes invalidate native normals; light-only changes reuse them except when shadow visibility needs recapture. PSS-07 delivers basic smooth lighting immediately; PSS-10 extends it to mode/band controls instead of leaving the pipeline awaiting future functionality.

### Ordered pipeline

1. Validate a snapshot and mark its scene/settings revision.
2. Derive render camera projection, subject fit/alignment, and native W×H target. Camera near/far exclude singular/frustum-invalid input.
3. Capture native normal/category data only when geometry/camera/framing/output changed. Flip GPU bottom-left rows once into top-left CPU layout; preserve all array alignment. Mask calibration reads only subject category.
4. PSS-15 captures shadow visibility and packed view depth in a separate native byte pass sharing geometry, projection, culling, depth behavior and categories. A lit ShaderMaterial derives from the installed Three `ShaderLib.shadow`, including its light uniforms and native shadow chunks; no assumption is made that the normal shader receives shadows. The same target is reused sequentially, with independent readback buffers.
5. Calculate continuous scalar illumination and linear RGB. Attenuate directional, not ambient, for shadows. Preserve subject/receiver region labels.
6. Apply signal controls. Smooth/flat reference mapping converts continuous RGB once to sRGB. Cel/discrete modes select ramp entries; palette mode uses nearest color. Dither is integrated into that selection, not applied to the resulting image afterward.
7. Process ground separately with explicit color/palette policy; create shadow-only receiver mask from visibility. No diffusion crosses category boundaries.
8. Generate native silhouette outline using the original subject mask, then composite outline behind subject and over ground. Effects never enter subject measurements or diffusion. Optional strict-effects palette mapping happens before writing effect colors.
9. Composite transparent or solid background last. With binary alpha this is selection, not blurred alpha blending. Zero RGB on fully transparent pixels.
10. Publish one immutable final `{width,height,rgba,revision}` frame and metadata, including subject/effect bounds and clipping. Final buffers cannot be reused/mutated during export; use ownership or a snapshot copy.

### Color and quantization

UI hex colors store opaque sRGB bytes; derive linear colors once for math, not on every comparison. Three uses a linear-sRGB working space and output conversion matters for display; custom data materials explicitly bypass display conversions. [Three color management](https://threejs.org/manual/pages/color-management.html). The following are application design decisions: CPU nearest-color uses squared Euclidean distance in linear RGB, lowest-index ties, then emits original palette bytes; ramp mode uses artist order and scalar thresholds rather than nearest luminance sorting. Reference-only GPU beauty rendering follows the same light formula and one final sRGB conversion; the authoritative before-image uses native continuous shading with the active normal treatment. Flat mode retains face normals in its before-image; comparison removes band/palette/dither/outline styling, not the selected normal treatment. This avoids a second normal capture solely for comparison.

### Implemented shading contract (PSS-10)

`domain/shading.ts` owns pure signal/ramp math and color-byte helpers; `pixels/nativeFrame.ts` consumes the existing normal/category capture and shared Lambert energies. Define `clamp01(v) = min(1,max(0,v))`. Scalar illumination is **`s = clamp01(0.2126*I.r + 0.7152*I.g + 0.0722*I.b)`**, where `I = ambient + directional*max(N·L,0)` in linear-sRGB, before base reflectance. Unit white illumination maps to 1; energies above 1 saturate rather than renormalizing against source intensities. Colored illumination changes placement through this luminance without tinting ramp entries.

Signal order is **`adjust(v) = clamp01((clamp01(v)-0.5)*contrast + 0.5 + brightness)^distribution`**. Contrast pivots around 0.5; distribution >1 favors shadows and <1 favors highlights. Cel/bands adjust `s` before selection. Continuous smooth/flat apply the same function independently to each linear `base*I` channel, then convert once to sRGB. Original bypasses all signal/tone controls, retaining continuous `base*I` with active normals and exact background. Base-color edits affect Original immediately; shadow/base/highlight become Final ramp colors only on explicit generation. No adjustment or color conversion follows exact ramp selection.

Thresholds are strictly increasing inside (0,1). For N entries, `rampCoordinate` linearly interpolates the knots **(0,0), (threshold[i],i+0.5), (1,N−1)**. One entry always maps to q=0. A non-dithered ramp chooses `min(N−1,floor(q+0.5))`; equality selects the higher artist index, regardless of its actual luminance. Input endpoints select first/last entries after signal adjustment. These half-integer crossings remain suitable for PSS-12/13 dithering.

Explicit generation samples shadow→base→highlight in linear RGB, with base at 0.5, and stores converted sRGB bytes once. N=1 uses exact base; N=2 uses exact shadow/highlight; all N≥2 retain exact endpoints and artist order. Count changes keep entries/boundaries via `setShadingLevels`, with visible removal disclosure and Apply. Generation is the only PSS-10 action replacing retained colors. Existing `setPaletteColors` retains its PSS-02 same-count/custom-threshold and changed-count/uniform-threshold contract for PSS-11's explicit palette operations.

`ShadingInspector` exposes Smooth reference (smooth+continuous), Flat shading (flat+continuous), Cel and Discrete bands. Cel and bands intentionally share the exact threshold mapper, without silently replacing the artist's count/colors; low level counts create broad cel regions. The banded modes have an independent normal selector and retain active thresholds when switching between tone modes. During a continuous-mode visit, the mounted inspector remembers prior boundaries for return; the version-1 continuous JSON shape still has no inactive threshold field. Level/color data live only in the existing ordered palette. PSS-11 extends these owners with the palette contract below; PSS-12 provides active Bayer controls; outline/ground controls remain hidden.

`NativeCapture` reuses one owned shader with a flat-normal uniform. Flat uses `normalize(cross(dFdx(viewPosition),dFdy(viewPosition)))`; smooth uses the inverse-transpose `normalMatrix` and interpolates authored normals. No geometry expansion, cloning or mode-triggered rebuild occurs. Model-view positions include each static mesh's full nested transform, so derivative normals handle nonuniform/mirrored scales. Real-GPU nested static-mesh fixtures verify transformed face direction and unchanged buffers; actual GLB/GLTF import remains PSS-16. Switching tone/signals/thresholds reuses capture; changing normal treatment recaptures. Before/final publications remain independently owned and guarded by the same revision/generation checks. Byte-normal quantization can move a surface very close to a boundary by GPU raster precision; CPU boundary equality is exact and same-environment settled output is deterministic.

Bayer rank matrices use `t=(rank+0.5)/(matrixSize²)`. For ramp dithering perturb the continuous coordinate by `strength*(0.5-t)*transitionWidth` before the same rounding/selection; transitionWidth is in shade intervals, bounded 0–1. Pattern scale uses floor(nativeCoordinate/scale). Palette mode perturbs linear RGB by a bounded threshold amplitude derived from palette spacing, then performs nearest-color selection. This simple vector perturbation is predictable, although not perceptually optimal; a more sophisticated pair search is unnecessary initially.

Blue noise replaces the rank threshold source with a fixed 64×64 tile, not per-frame random noise. Prefer a bundled single-channel tile with provenance/hash and no network runtime requirement. Christoph Peters' database publishes tileable textures under CC0; choose one fixed tile and do not follow temporal randomization advice for this deterministic app. [Author's blue-noise publication and licensing](https://momentsingraphics.de/BlueNoise.html). If unavailable, generate a deterministic void-and-cluster tile offline and document generation; never relabel random noise as blue noise.

Floyd–Steinberg runs on CPU in top-left row-major order. For ramp mode quantize continuous scalar ramp coordinates and diffuse error in that domain. For palette mode diffuse linear RGB error. Use exact weights 7/16, 3/16, 5/16, 1/16 and strength-scaled error propagation. Skip transparent/different-region neighbors without weight renormalization. Maintain reusable floating-point current/next error rows. Strength zero dispatches directly to the same undithered mapper before any algorithm-specific processing. No pattern scale applies to diffusion. Tests include small expected arrays plus palette/mask invariants.

### Implemented native fit (PSS-08)

`scene/pixelFraming.ts` traverses visible subject-layer mesh vertex/index buffers (respecting draw ranges), applies each matrixWorld and the rolled camera view/projection, and measures actual projected vertex extents in native pixel units. It does not substitute world Box3 corners or scale mesh transforms. Orthographic/perspective both use one uniform projection multiplier and translation; depth/foreshortening and normal space are preserved. Manual mode uses the original derived camera. Near/far crossings and projected axes thinner than 1e−8 of the larger extent reject fitting and capture the usable manual projection with a notice. Singular near-plane vertices retain the depth failure reason.

The analytic scale is `min(effectiveWidth / projectedWidth, effectiveHeight / projectedHeight)`. A parity-aware phase aligns the predicted occupied center to the native grid. `calibrateFit` makes at most **12 native samples**, searching uniform scale within **[0.875, 1.125]** of that estimate with alternating zero/±quarter-pixel phase shifts. It prefers no overflow, then minimum slack, and stops when a nonempty mask fits both effective axes and fills at least one. Arbitrary shapes need not fill both axes. It restores the best sampled projection and makes **one final native capture** after placement (13 total maximum); empty/failed calibration reports its achieved result and a notice. A projected-vertex guard detects calibration clipped by the canvas. No follow-up invalidation or unbounded loop is scheduled.

`pixels/subjectBounds.ts` measures only top-left **category alpha 255**, excluding cleared zero, reserved receiver 128, helpers, display backgrounds and future effects. It returns inclusive integer occupied bounds as `{x,y,width,height}` or `null`, never requested dimensions. The framing report accompanies the canonical frame; only small capture-revision-keyed metadata is copied into transient `nativeFraming` store state after guarded publication. Pending captures replace old measurements; failure/disposal clears metadata. No typed buffers enter React or scene JSON.

Alignment places the measured subject directly within the padded drawable canvas: leading edge is padding plus `floor((drawableSize − measuredSize) / 2)` for center, zero spare for left/top, all spare for right/bottom. Offsets are added afterward (+X right/+Y down) and can clip intentionally. The fit box is a maximum size, not a second nested alignment container. Requested oversized boxes are retained; effective dimensions clamp independently to drawable area with a visible notice. Empty padded areas reject atomically through existing validation. Clipping combines projected-vertex/frustum checks and final placement bounds; actual dimensions describe visible pixels only. Outline extents are published separately by PSS-14; PSS-15 adds conservative receiver/shadow extents including softness.

`NativeCapture` retains the fitted normal/category buffer, report and view matrix until capture revision changes. Light/palette/background edits reuse them; geometry/orientation/canvas/framing changes recompute. All rasterizations reuse its native target and synchronous readback under the existing renderer-state `finally`, generation/revision publication guard and explicit Retry owner. `FramingInspector` provides both modes, nine alignments, box/offset/padding controls, requested/effective/actual output, notices and a framing-only reset. `CameraController` dynamically locks pan/zoom in pixel-fit mode, preserving orbit, gesture ownership and manual controls on mode switch. No second authoritative camera pose, image resampling, dependency or new scheduler was introduced.

## Scheduling, performance, and recovery

Use one requestAnimationFrame invalidation scheduler; rendering is idle when unchanged. An export request pins one settings/resource snapshot until its native capture and processing complete. Only one export transaction is active; disable repeat export clicks while busy. This is the same renderer and processor with explicit job ownership, not a second export pipeline. Settings debounce at 400 ms with a non-renewing 2 s deadline; pagehide/visibility-hidden and disposal flush the latest configuration. Timers/listeners/subscription detach on teardown. Named operations commit synchronously; a queued autosave reads the current atomic snapshot, so it cannot replay a prior partial configuration.

Storage getter/read/write exceptions remain visible and leave current edits and named snapshots usable in memory. Failed writes retain their dirty slots for explicit retry; a retry after unreadable initial access reads/validates first, merges previously saved named presets with session entries, and preserves current edits. Case-insensitive name conflicts retain both under a descriptive recovered name. Malformed/unknown-version data blocks writes only to its own key; the raw original is downloadable with current in-memory work. Explicit replacement confirms in the app, writes the raw original to a unique `:recovery:<uuid>` key, then commits current/session data. Backup failure keeps the original key protected. Unrelated keys are never cleared. Recovery JSON is a local backup for inspection/manual recovery; no additional scene import format is claimed.

`PresetManager` provides named save/restore, confirmed overwrite/delete, retry, local recovery download and backed-up replacement. `LocalSaveStatus` keeps storage issues visible with the preset panel closed. Three complete immutable snapshots cover canonical blue sphere, directional cube and dithered limited colors. All restore paths use the existing validated `restoreSettings` action. It now cancels older pending imports only after validation, preventing late completions from replacing the restored scene. One changed snapshot publishes settings/revisions together, causing one native capture/process. View-only resizing may trigger a separate presentation draw without native recapture. Section/palette/full-scene resets retain saved names and existing reset boundaries. Editors remount on preset restore to discard stale drafts and inactive-mode UI caches.

`ImportController.select(files, expectedDescriptor)` preflights/parses using existing PSS-16 limits and rejects a bundle whose SHA-256/format does not match a pending saved descriptor; it releases rejected resources and leaves settings untouched. Both Subject and the viewport expose pending reselect. The viewport offers explicit built-in sphere fallback while preserving transforms, camera, lighting and style. Matching same-session assets can be reused. No File, object URL or model bytes survive reload or enter JSON. This preserves the existing reference scheduler, resource owner and pinned PSS-17 export path.

### Implemented palette contract (PSS-11)

`domain/shading.ts` extends the existing signal/ramp owner with `preparePalette`, `nearestColorIndex` and `resampleShadingRamp`. A WeakMap keyed by immutable validated `palette.colors` caches decoded linear RGB and original byte triples; unchanged sections retain identity through the store, so light/signal edits reuse the cache. No pixel comparison decodes a color or sorts/deduplicates entries. Distance is unweighted squared Euclidean linear RGB `Σ(input−entry)²`, not a perceptual metric. Only strictly smaller distance replaces the winner, making exact ties and duplicates select the lowest artist index. One entry always wins; empty palettes are rejected before processing.

`processNativePixels` preserves PSS-10's order: continuous linear base×illumination → channel signal controls → nearest match → original byte write. Smooth/flat encode the continuous result exactly once; cel/bands use the existing scalar illumination mapper; both fixed selection paths bypass encoding and all later tone adjustment. Saturation means clipping energy/signal to [0,1], not an HSV/HSL saturation transform. Intense illumination may flatten allocations at endpoints. Transparent pixels stay RGBA zero.

`PaletteInspector` reuses ColorField for manual picker/hex edits. Picker input and final change both commit through validation, with no duplicate dirty revisions. Artist-order move, edit, append, remove, preset and reset actions stay in the existing store lifecycle. Apply levels retains the PSS-10 behavior unchanged. Explicit resample follows the ordered piecewise linear-RGB color path, storing converted bytes once; exact existing knots/endpoints bypass conversion, N=1 keeps the first entry, and one-entry growth repeats that byte. The generator and resampler share the same interpolation/encoding helper. Resampling never occurs on an ordinary count edit. Changed counts for explicit list replacement/resample rebuild active boundaries evenly; same counts retain boundaries. Clear UI copy discloses replacement/removal before applying.

`domain/paletteInterchange.ts` defines palette-only JSON `{schemaVersion:1,colors:["#RRGGBB"],effectPolicy:"explicit"|"strict"}` with no unknown fields; all fields are required. Lists accept comma/whitespace-separated six-digit hex tokens with optional # and retain current policy. Both formats preserve order/duplicates, normalize case, limit count to 1–32 and input to 16 KiB. Shared `validatePalette` handles the same color/count/policy rules used by complete scenes. Store `importPalette` validates first, then commits colors, policy and active threshold count once. Rejected input changes no state or revision. FileReader stages local file text, aborts on replacement/text edits/unmount, and never applies before the explicit Import action. Export provides current read-only text and a small encoded data-URL download; no persistent object URL, external service or graphics resource is created. JSON includes policy; hex omits it. Thresholds, tone and scene data are intentionally outside this palette format.

Effect policy is active now for solid backgrounds. Explicit writes configured background bytes; strict decodes/matches that configured color before writing original palette bytes, independent of subject signal controls. Original remains continuous with the configured background. Future outline/ground/shadow stages must honor this same explicit/strict policy before their final writes, excluding transparent alpha and preserving independent subject/category masks; they must never post-tint a selected palette color. Strict effects do not make continuous subject modes palette-constrained. No future effect algorithm was implemented here. PSS-12 can perturb continuous linear RGB before `nearestColorIndex` or existing ramp coordinates before rounding, while preserving cache, exact final writes and Original ownership.


### Implemented ordered dithering (PSS-12)

`domain/orderedDither.ts` owns immutable Bayer ranks, native threshold lookup and prepared scalar/RGB quantizers. Starting with `[0,2;3,1]`, each expansion uses the quadrants `[4B,4B+2;4B+3,4B+1]`. Thresholds are `(rank+0.5)/N²` at `floor(x/scale) mod N, floor(y/scale) mod N`. NativeCapture already flips GPU rows once; processing addresses that top-left buffer as `x=pixelIndex mod width`, `y=floor(pixelIndex/width)`. Coverage does not reset phase. No CSS, DPR, object pose, time or random input enters this lookup.

Ramp selection follows the specified `q + strength*(0.5-t)*transitionWidth`, then `floor(q+0.5)` with both ends clamped to valid artist indices. Width is in shade intervals, 0–1, so only neighboring shades mix. None/zero strength returns the existing `rampIndex` path before ordered work; zero width and a single shade also use it. `createPaletteQuantizer` likewise returns the existing `nearestColorIndex` path at None/zero. PSS-13 dispatches sequential Floyd–Steinberg separately; these threshold-only factories reject a direct nonzero diffusion request rather than approximating it.

Palette amplitude is **`A = minPositivePairDistance(linearPalette)/sqrt(3)`**, bounded to [0,1]. No positive pair (one color or all duplicates) gives A=0. For each subject pixel, shift all continuous adjusted linear-RGB channels by **`strength*(0.5-t)*A`**, clamp each to [0,1], then run the existing squared-linear-distance matcher. This bounds the unclamped vector displacement to less than half the minimum distinct palette distance at full strength. Duplicates neither change amplitude nor first-index tie behavior. The smallest distinct spacing is a conservative choice; a near-duplicate may weaken dithering for the whole palette, and this neutral-axis shift is not perceptually optimal. Width is irrelevant to nearest mode and is retained only for a return to ramp modes. A WeakMap keyed by the existing prepared palette caches the pairwise amplitude across processing edits, without changing artist order or decoded-entry ownership.

`processNativePixels` constructs only the active quantizer and accepts optional dither/canvas metadata alongside the existing shading/palette input. Active ordered mapping requires exact native dimensions and rejects mismatched buffers. The full settings already pass from NativeCapture, so its capture/shader/framing owner is unchanged. Only category 255 enters shade decisions; receiver 128 remains reserved and receives the existing background behavior until PSS-15. Background selection and alpha are independent, including strict effect mapping. Every chosen ramp/palette color is written as stored bytes, with no later RGB perturbation. Continuous tone bypasses dither entirely. Original is still copied before styled processing.

`DitherInspector` uses the existing validated section action, NumericField/SelectField and disclosure. PSS-12 initially exposed None and Bayer sizes; PSS-13 extends it to all six choices below. Threshold controls provide strength 0–1, integer scale 1–8 and ramp-only transition width. Continuous modes show an inactive explanation and hide numerical controls without modifying saved dither. New Bayer selection defaults to strength=width=1, scale=1; switching sizes retains values. None's version-1 serialized shape still contains only kind; the mounted editor remembers prior ordered controls for quick reversible toggling. Reset dithering restores None, resets that UI memory and leaves other scene sections intact. No schema/default/store-revision change, dependency, graphics allocation, worker or second scheduler was added. Dither commits dirty style only; view changes skip processing. Development diagnostics now expose actual `devicePixelRatio` so real browser zoom can verify this separation.


### Implemented blue noise and sequential diffusion (PSS-13)

`domain/blueNoise.ts` decodes and freezes the 4,096-byte single-channel tile from `assets/blue-noise/thresholds.hex` once. The unmodified grayscale RGBA source PNG and README retain Christoph Peters' CC0 provenance and archive/PNG/raw SHA-256. Raw channel extraction performs no display/gamma/ICC conversion. Each byte 0–255 appears 16 times; threshold is `(byte+0.5)/256`. Native lookup uses floor(coordinate/scale) modulo 64 at fixed top-left origin. `orderedDither.ts` selects Bayer or blue-noise threshold sources through the same ramp-width and palette-spacing formulas; Bayer matrices, thresholds and results are unchanged. The offline `scripts/check-blue-noise.py` verifies raw decode/hashes/histogram and computes direct periodic DFT evidence, including binary threshold views. No runtime asset fetch or random input exists.

`domain/errorDiffusion.ts` supplies scan-owned scalar/RGB quantizers behind the same `(input,x,y) => paletteIndex` boundary. Each factory is used for one monotonically increasing top-left native scan; callers skip ineligible pixels. It allocates exactly two `Float64Array(width*channels)` rows (one scalar or three RGB channels), swaps them and clears the finished row for reuse, including entirely skipped rows. There is no full-frame float buffer or per-pixel residual allocation. Rows are fresh for the next processing call, so no residual survives a frame/settings edit. At width 256, the row storage is 4 KiB scalar or 12 KiB RGB.

For ramps, adjusted illumination enters existing `rampCoordinate`; accumulated error is added to q, common half-up `rampIndexFromCoordinate` selects a bounded artist index, and residual is q minus that index. Palette input is adjusted continuous linear `base*illumination`; accumulated RGB error enters the unchanged nearest matcher (squared linear distance, stable lowest-index ties), and residual is that adjusted RGB minus selected decoded RGB. Accumulated inputs/residuals are not clipped: clipping would discard quantization error and bias diffusion. Base signal adjustment remains bounded as before. Only original palette bytes are written afterward; alpha is never part of the error domain. One-color mapping has an exact constant shortcut.

Error from the selected pixel goes right 7/16, down-left 3/16, down 5/16 and down-right 1/16, multiplied by strength. Every neighbor is checked against native bounds and the source category before writing. Missing/different-category weights are dropped without renormalization. No residual is forwarded through a skipped mask pixel or across an empty row. `processNativePixels` invokes subject quantizers only at category 255; category 0 and reserved receiver 128 retain background handling, and outlines/effects remain outside matching. A future receiver pass must keep its own eligible category without adding background/outline colors to subject palettes.

The processing entry normalizes None, continuous tone and exact strength zero to the common disabled path **before algorithm selection, dimension checks or diffusion-row allocation**. Every nonzero active algorithm requires matching native dimensions. NativeCapture preserves continuous Original first, processes Final synchronously, then applies its existing generation/revision publication guard and owned-frame copies. Dither changes still dirty style only. Diagnostics now split `originalMs` (lighting plus Original copy), `styleMs` (Final lighting/quantization), and `publishMs` (final publication/copy) alongside aggregate `processMs`, `captureMs` and `readbackMs`. Capture/readback measurements are retained from the last capture, not repeated costs on style edits; capture includes readback/calibration. Zero/sub-millisecond entries reflect browser timer resolution. No FPS promise, worker, second scheduler or GPU resource was introduced.

`DitherInspector` offers the required six choices. Bayer/blue noise share retained scale 1–8 and ramp width 0–1; palette mode hides width. Diffusion has strength only, with scan/mask help and an explicit reason that scale/ordered width are irrelevant. Switching algorithms retains strength and remembers threshold parameters locally; serialized active unions are unchanged. Reset dithering/scene follows the prior boundaries. Browser evidence covers actual production WebGL sphere/torus frames and a local production-quantizer gradient harness, with an independent full-image Python FS reference (different storage strategy), mask/alpha/membership/repetition checks and measured 64/256 stages. All task results and scope limits are recorded in PROGRESS.md.


### Implemented native silhouette outlines (PSS-14)

`pixels/silhouetteOutline.ts` implements the binary square/Chebyshev rule: a pixel is in the dilation if any original subject-category pixel is within `max(abs(dx),abs(dy)) <= thickness`; the ring subtracts every original subject pixel. Two separable bounded passes read unchanged category/horizontal sources, using a one-byte horizontal scratch and one-byte binary ring per native pixel. Radius is validated as integer 1–8; dimensions and separate mask ownership are checked. Only alpha category 255 contributes. Category 128, background, helpers, existing outline pixels and later ground shadows never seed dilation. There is no flood-fill: hole edges grow inward by the same radius, large hole centers remain empty and narrow holes can close deliberately.

The compositor copies the cached styled underlay, then selects opaque outline bytes only at ring pixels outside subject. Thus subject wins over outline, outline wins over receiver/background, and untouched transparent pixels retain the underlay's canonical zero RGBA. Initializing the existing underlay with its background before this binary selection is equivalent to the ordered pipeline's final background selection; it does not change the morphology source or blend colors. Future receiver rendering must supply its own underlying pixels/categories while preserving this ordering. No ground/shadow implementation was added here.

`domain/shading.ts` shares `resolveEffectColor` between solid background and outline. Explicit returns the original request. Strict selects an active palette entry by existing squared linear-RGB distance with stable first-entry ties, then writes its stored bytes. The inspector preserves the requested hex while showing the resolved entry; explicit colors outside the palette disclose at most one extra outline color. Effect colors never enter dither selection/error rows: compositing follows all quantization, and normals/categories remain unchanged. Subject palette guarantees in continuous versus quantized modes remain as documented in PSS-11.

`NativeCapture` owns one additional styled RGBA cache plus the two one-byte mask arrays, all reused by size and released on dispose. At 64×64 these add 24 KiB; at 1024×1024 they add 6 MiB. The existing raw, normal and output arrays retain their ownership. Shared unchanged settings sections and the processed capture revision key the styled/Original cache. Outline-only commits skip Lambert evaluation, quantization, original copying and native capture/fit; thickness changes rebuild the ring, and color changes reuse it. Ring geometry is keyed by capture revision and thickness. Other style-section changes conservatively reprocess styling, including policy changes that also affect the background. The store revision/schema/scheduler contract is preserved, with no new scheduler or graphics resources. A style attempt invalidates its cache before writing so superseded work cannot contaminate a later reverted snapshot. Publication still checks generation/revision/disposal and copies completed Final bytes; Original bytes can be shared across outline-only revisions because they are never reused as work storage.

`NativeFrame.outline` is null when disabled and otherwise contains `extent` (unclipped subject-plus-dilation bounds), `visible` (canvas-clipped bounds), exact ring `pixelCount`, `clipped`, resolved `color` and `thickness`. Empty captured subjects have null bounds and zero pixels. Extents describe dilation of the **captured** mask, not reconstruction of off-canvas geometry. Subject `FramingReport` and camera are never changed by an outline edit. Small revision-keyed `nativeOutline` metadata enters transient store state only after guarded publication and clears on failure/disposal. `OutlineInspector` and the workspace display it with a clipping notice; no padding or output resizing occurs. Original has null outline metadata and remains continuous.

The inspector uses the existing validated settings union, NumericField, ColorField and section reset. Its mounted local memory retains settings through None/Silhouette toggles; Reset outline clears that memory and changes no other section. Reset scene remounts the editors and restores None. Diagnostics distinguish `processes` from `composites` and report `compositeMs` alongside the last processing/capture timings. Retained process/capture timings are not repeated costs for an outline-only edit. Node fixtures, independent Python square-stamping of actual Chrome frames, 16/64px zooms, policy/background/dither switches, comparison and remount evidence are recorded in PROGRESS.md. PNG encoding remains PSS-17.


### Implemented directional visibility and receiver (PSS-15)

`scene/groundReceiver.ts` owns one unit PlaneGeometry/MeshBasicMaterial on ground layer 2, transformed into a finite double-sided XZ plane. It never casts shadows. The subject retains its earlier front-side culling (double-sided Plane subject); normal and visibility override materials select the same side per object. Fitting captures subject layer 0 alone and retains that original subject-normal mask for measurement and outline morphology. A settled combined normal/category pass enables ground on the same fitted camera, preserving physical depth occlusion. Ground should sit below the subject. Ground intersections can hide subject pixels but never redefine its measured fit or seed outlines.

`scene/directionalShadows.ts` uses the existing directional light, one fixed **1024×1024 BasicShadowMap**, no PCF/VSM or additional source. Its light-space XY frustum fits the transformed caster Box3 with a 5%-of-diagonal margin, rather than wasting map texels on an arbitrarily large receiver. The depth interval includes subject and finite receiver. Directional light position is a derived rendering resource; artist settings remain untouched. An alternate up vector handles an overhead light. Ground receiving pauses at surface-to-light Y ≤ 0.01 (about 0.57° above horizontal); self shadows still work. This avoids unstable grazing ground shadows without rotating the artist's light.

Caster depth uses front sides (double sides for plane geometry), a fixed depth bias −0.00001 and normal bias **`(bias ?? 0.5) * max(frustumWidth,frustumHeight)/1024`**. Optional `shadows.bias` is validated from 0–2 map texels, preserving old version-1 scenes that omit it. All other active fields retain their required validation. Zero is deliberately available to inspect acne; 0.5 is the tested default. The map remains allocated at fixed size while disabled; `castShadow=false` plus demand-only updates stops map rendering. NativeCapture owns its disposal and clears the light's map reference before the light owner disposes. No second renderer, GPU visibility target, package, remote asset or dependency change was introduced.

The visibility ShaderMaterial clones **installed r186 `ShaderLib.shadow.uniforms`**, sets `lights=true`, retains its world-position/shadow-map chunks and writes `getShadowMask()`. This is a separate working native pass, not shadow support added by assumption to the normal shader. It replaces the ShadowMaterial color/alpha result with **R=visibility, GB=16-bit view depth, A=category** and removes display conversion. Depth uses a scene-bounded origin/span shared with the CPU filter; subject and receiver share the same view/projection, depth buffer rules, culling, category uniform and one top-left row flip. Native normal categories and visibility categories are checked before filtering and independently verified across saved real Chrome frames. `scene/nativeRender.ts` restores all prior renderer/scene/GL capture state on success or failure. No category alpha reaches published RGBA.

`pixels/shadowVisibility.ts` filters visibility at integer radius 0–4 before illumination. Hard/radius 0 copies visibility exactly. Soft uses a square native neighborhood normalized over eligible samples only. Both endpoints and every rounded intervening sample must retain the category; normal cosine must be ≥0.85 and view-depth difference ≤ two native world-pixel diagonals per step plus depth-code tolerance. Thus receiver/background, unrelated faces/depth layers and gaps do not bleed into the kernel. This is an artistic screen-space treatment, not physical penumbra simulation; it can truncate at silhouette, surface and receiver edges. Float work and byte passes reuse allocations by native size.

For subject pixels, **`V_effective = 1 − strength*(1 − filteredVisibility)`** when the self toggle is enabled, otherwise 1. The existing Lambert contract becomes **`I = ambient + directional*max(N·L,0)*V_effective`** before signal controls, dithering and unchanged ramp/nearest algorithms. Original shares this lighting and active normals, bypassing subject styling/outline. Ambient is not multiplied by visibility.

Receiver rendering deliberately selects between two exact effect colors rather than introducing continuous tints. Let `U=clamp01(luminance(ambient+direct))` and `S=clamp01(luminance(ambient+direct*V_effective))`. Covered shadow density is **`U>0 ? max(0,1−S/U) : 0`**. A fixed native Bayer 4×4 midpoint threshold selects opaque shadow color or the exact visible receiver color; shadow-only chooses zero RGBA for the latter. Ambient-only and disabled ground shadows produce no shadow-only coverage. Strict policy resolves both colors through the existing nearest-linear-RGB palette mapper before writing; explicit policy discloses at most two additional colors. Receiver pixels do not run subject quantizers or emit/receive subject FS error. Outline compositing reads the preserved subject mask and selects above receiver; backgrounds remain final binary selection.

Existing capture and shadow revisions remain authoritative. Receiver geometry changes conservatively refit subject-only data and combined normals; appearance/color reuses them. Light direction and any shadow setting recapture visibility/map (including strength/radius/color as the existing conservative revision contract requires), reusing normal data. Palette, background, outline, signal and intensity/ambient changes reuse visibility. Preview changes perform presentation only. Native topology is SVG-only; runtime no longer writes the preview mesh-edge flag into the caster material, which would otherwise corrupt future shadow maps after a light edit.

`NativeFrame.ground` and transient revision-keyed `nativeGround` report conservative projected receiver and caster-box shadow footprint bounds, expanded by the soft radius, plus canvas/depth/finite-receiver clipping. Soft bounds use a conservative projected receiver polygon containment check. These are potential effect bounds, not an exact count of opaque shadow pixels; hidden or clipped caster geometry is not reconstructed. No canvas enlargement occurs. Failure/disposal clears reports and resources. Diagnostics report successful visibility/receiver captures, shadow updates, actual map/frustum/bias, separate byte/float buffers and visibility/filter timings. Light presets retain receiver/shadow settings; Reset lighting and Reset ground & shadows have distinct boundaries. Factory scene defaults still disable both effects.


### Implemented bounded model import (PSS-16)

`import/localFiles.ts` bounds a selection to 25 MiB / 64 files and resolves relative companion paths only against explicitly selected files, with a unique-basename fallback for normal multi-file pickers. Absolute, scheme, traversal, query/hash, control-character and ambiguous paths fail. Base64 buffer/image URIs are validated; decoded buffer totals also stay within 25 MiB. LoadingManager remaps buffer URIs to owned blob URLs. Every URL is revoked after settled loading/abort; remote references fail before GLTFLoader, including image references whose appearance will be discarded.

`import/modelDocument.ts` reads bounded GLB 2.0 chunks or glTF JSON, validates indices/spans/counts, dense attribute layouts, required extensions and static scene graphs before parsing. Caps: 250,000 vertices and triangles, 2,048 declared nodes, 2,048 expanded mesh parts, depth 64, 4,096 accessors/views. Counts conservatively include all declared mesh nodes/instances. Multiple parents, cycles, invalid transforms, sparse data, compression, points/lines/strips, skins/skin attributes, morphs, GPU-instancing extensions and animations are explicit errors. Required material-unlit and punctual-light extensions can be ignored; other required extensions are rejected. These are initial support limits, not decoder TODOs. The selected scene alone is parsed; optional extras, cameras, lights and appearance extensions are stripped.

**Decision:** validate/hash image companions, then remove imported materials/textures/images before parsing. The studio never uses imported appearance, so decoding it would add unnecessary image dimensions/decompression risk and unused GPU/bitmap ownership. A minimal material placeholder still lets the installed GLTFLoader create ordinary meshes. No texture fidelity is claimed. Loader interim bounds are replaced by exact validated vertex bounds before publication.

`import/modelAsset.ts` uses installed GLTFLoader with tracked geometry/material dependencies and a local LoadingManager. It checks actual parsed vertex/index/normal/world-transform/bounds data, computes missing normals, overrides mesh materials with one studio Lambert material and tracks shared resources in Sets. Loading errors await pending dependency work before cleanup; no parsed content reaches a renderer until validated. Imported textures/bitmaps are avoided entirely; defensive material disposal also deduplicates texture/bitmap sources. Runtime assets use reference counting: the controller retains a store reference, each SceneSubject content clone retains one runtime reference, and final release disposes all shared geometry/materials once. Pending reads/parse callbacks observe AbortSignal and revision checks. Cancellation cannot preempt synchronous JavaScript parsing, but all work is bounded and a cancelled result cannot publish.

`import/importController.ts` stages imports independently of scene settings. Only the latest valid asset publishes its serializable descriptor. Failures keep the current asset/settings; cancellation, newer selection, primitive return, reset and unmount invalidate older work. Transform edits made while loading are preserved when the descriptor commits. Settings changes stay atomic; model status is transient. `StudioStore.assets` holds runtime ownership outside Zustand's serializable settings. `App` releases it on teardown; renderer remount/context retry retain the controller asset. No files/binary storage/localStorage writes are introduced.

`SceneSubject` retains the existing user transform parent and normalization child. Primitives keep their prior dimensions; model normalization uses scale `2 / longestAxis` and translation `-center * scale`. Cloned hierarchy transforms remain intact; shared geometry is reused. ReferenceRuntime selects primitive or asset content at its existing replacement boundary, then uses unchanged native normals, fitter, visibility/shadows, palette/dither, outlines and presentation. There is no model-specific pixel scaling, canvas or export path. Missing runtime descriptors show reselect guidance instead of silently rendering a substitute; PSS-18 can restore the same descriptor/settings and request reselect. Hashes cover selected file names/content in sorted path order. No runtime File, URL, mesh or frame belongs in settings JSON.


### Implemented measured polish and lifetime contract (PSS-19)

Measured stage costs and the reproducible browser method are in [evidence/PSS-19.md](evidence/PSS-19.md), with raw per-edit records. Main-thread synchronous processing remains: radius-4 visibility filtering was the measured bottleneck. `shadowVisibility.ts` prepares fixed kernel rays once and caches each source pixel's repeated category/normal/depth eligibility in at most 81 bytes per call. It retains the same intervening-sample rule, arithmetic predicate, row-major accumulation order and Float32 outputs; a direct-filter oracle fixture verifies exact equality for every radius. No approximate/separable filter, resolution reduction, dither substitution or worker was introduced.

Store dirty revisions retain their conservative contract. NativeCapture additionally keys GPU visibility by capture revision, directional position/target and shadow enable/self/ground/bias settings. Strength/color changes reuse visibility and filtering; radius changes reuse visibility and filter it again. Capture/resize invalidates both caches. Color/intensity/ambient/style/view edits do not render the shadow map. Disabled shadows perform no GPU visibility work. Readback remains synchronous, so there is no transferred-buffer owner or asynchronous pixel job. Published and pinned-export arrays retain the existing detached-copy ownership and generation/disposal guards.

Native timing fields now describe the latest update, zeroing skipped stages rather than reporting old captures as current work. Capture includes subject fitting/readback; visibility includes receiver/map work and effect readback; CPU processing includes Original plus Final; filtering, outline composition and frame-copy publication are separate. Runtime timings add subject/camera preparation, helper/layout presentation and total render callback time. Native 2D upload and metadata publication are included in the whole callback, not separately timed. They exclude later React/browser paint; the browser harness also records long tasks and deliberately delayed event/diagnostic round trips. Diagnostics remain development-only and non-polling.

Transient render-busy status uses the existing operation status and clears on completion, missing-model guidance and disposal. It changes no dirty revision and keeps inputs usable. Current scene status compares normalized factory snapshots or stored named snapshots to actual validated settings, independently of the selected Restore source. Current palette status likewise distinguishes actual colors from a proposed preset. Existing errors, independent resets, panel focus recovery and import/export/storage recovery remain connected.

CSS-gradient/image-tile checkerboards reproduced stripes under layout changes in Chrome. PreviewPresentation now owns an opaque native-size checker canvas behind each clean native Original/Final canvas. Backdrops are filled only on first publication/size change, toggled for presentation only, and zero-sized/removed on disposal. The viewport therefore owns **five** canvases (one hidden WebGL, two exact RGBA, two backdrop), still one WebGL context and no extra GPU render target. Neither checkerboard nor helpers enter export bytes.

ReferenceSession mounts/disposes its runtime in a **layout effect**. This matters because installed OrbitControls.disconnect removes its document interceptor from `host.getRootNode()`: passive cleanup after React detachment used the detached host and leaked one document keydown listener per remount. Layout cleanup keeps the host attached until controls/listeners/observers/jobs/resources are disposed. A component lifecycle regression test uses real OrbitControls with a scoped renderer substitute; actual Chrome cycles verify the listener/heap/GPU plateau and forced loss/Retry. No canvas substitute supplies pixel evidence.
